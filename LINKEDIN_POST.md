🚀 Building an End-to-End MLOps Platform with Kubeflow + MLflow

I’ve been working on a hands-on **Customer Churn Prediction** project to understand how machine learning workflows can be designed and operated in a Kubernetes-native environment.

The current implementation combines **Kubeflow Pipelines + MLflow + PostgreSQL + MinIO**.

### 🎯 Project Objective

The objective is to build a reproducible, Kubernetes-native ML workflow that covers the lifecycle from dataset creation and validation to model training, evaluation, experiment tracking, and artifact management.

### 🔧 What I have implemented

✅ Kubeflow Community Distribution 26.03.1

✅ Kubeflow Pipelines

✅ Synthetic Customer Churn dataset

✅ Data validation

✅ Data preprocessing and categorical encoding

✅ Train/Test split

✅ RandomForest model training

✅ Model evaluation

✅ Accuracy, Precision, Recall and F1 metrics

✅ MLflow 3.16.1 experiment tracking

✅ PostgreSQL backend for MLflow metadata

✅ MinIO S3-compatible object storage

✅ ML model and artifact logging

✅ CSV, JSON and text artifact storage

✅ End-to-end Kubeflow → MLflow → MinIO integration

### 🔄 Current Workflow

Customer Churn Dataset

→ Validation

→ Preprocessing

→ RandomForest Training

→ Evaluation

→ MLflow Tracking

→ PostgreSQL Metadata

→ MinIO Artifacts

The next stages of the project will extend this workflow with:

➡️ Katib Hyperparameter Optimization

➡️ Distributed Training

➡️ Kubeflow Model Registry

➡️ KServe Model Serving

➡️ Prediction API

➡️ Monitoring and Observability

➡️ CI/CD and GitOps

This project has been a great way to connect **Kubernetes, MLOps, model lifecycle management and cloud-native infrastructure** into one practical workflow.
